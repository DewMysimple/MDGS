# 新版四卷源与导出真实性复核

本目录的 `validation-native-new.json` 与 `validation-assets-new.json` 由独立验收脚本生成，不以旧审计报告中的 `pass` 或布尔字段代替当前文件复核。运行时不保存或改写输入、交付 `.blend`。

## 复核范围

- 四份“牡丹”输入、四份活跃可编辑交付的当前 SHA256，与当前网页清单的来源信息对应。
- Blender 5.2 原生重新打开输入和交付，共八次；逐帧扫描四卷全部整数帧的 `hide_render`，重新计算每个已导出的相机位置、旋转、FOV 和物体矩阵样本。
- 每个物体在首次可见帧重新求取 evaluated mesh、三角面和 UV，展开网页索引后逐坐标比较；初始矩阵、场景帧范围、帧率、渲染尺寸及标记逐项核对。
- 当前交付中打包的图像原始字节，逐一与网页清单的 `sourceSha256`、图片 ID 对应；每份 WebP 当前 SHA、尺寸与实际完整像素解码也核对。
- 读取实际 `prepareScene.ts` 运行 CPU 区间检查：新版首末帧完整保留，源进度采样不被旧结束帧截断，全部可见性边界可还原。当前新版保留作者时间0..1，旧版才用相机距离映射；相机停留期间仍必须保留源主体动画和显隐，不能压缩掉第三卷后段。

四卷导出网格数为149／58／79／53；独立图像为99／35／66／44，共244张。首卷149个网页物体中45个在首帧可见，104个在后续帧出现。原生第150个 MESH“主体 · 03_中央花车巡游与曲水”在3024个整数帧中始终隐藏，所以未进入导出；编辑辅助 CURVE 也始终隐藏。不能把二者算作丢失画面。

第二卷的第一标记原始帧为1，而实际源播放范围从33开始；网页保留 `authoredFrame:1` 并将入口节点放在33。第三卷9个“参考全景”标记仍保存在完整 markers，相机采样也保留，交互 stops 仅为9个正文节点。

首卷输入原件仍保留一张未打包的旧绝对路径图片；交付副本已打包精确原图。验收要求交付零缺图，并将该图片打包字节与网页来源 SHA 核对。输入原件未因验收而保存。

## 复现

先运行原生只读复核，再运行资源检查；后者要求前者的清单 SHA 与当前文件一致：

```powershell
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --disable-autoexec --python scripts/validate-new-scroll-native.py
$env:MDGS_PYTHON='指向包含 Pillow 的 Python 可执行文件'
node scripts/validate-new-scroll-assets.mjs
```

网页普通运行不需要 Blender 或 Python；它们只用于源文件制作及验收。

## 证据边界

这组验证不启动浏览器，不证明文字避让、首页像素相似度、按钮行为、音乐听感、动态帧率或设备兼容性。物体网格形状是在首次可见帧比较，源矩阵动画与可见性按上述全轨道范围核对；网页仍以未打光绘画表面近似 Blender 程序纸张、灯光和噪声着色，不宣称逐像素原生渲染一致。浏览器实际画面与交互另由网页验收报告证明。
