## 组件接入

NarrativeCalligraphy接收chapterId、progress、stops，以及可选active和placement。挂到实际.painting内部；active应在真实世界就绪并可交互后开启。原canonical及annotations文字应同时退役，避免重复题字。新Blender四卷审计未含FONT对象。

placement的x/y/width/height是相对于实际画心的0—1矩形，dense开启极淡绢纸衬底，orientation可为vertical或horizontal。优先由实际画面留白或场景占用检查提供安全矩形；默认桌面右侧竖题，手机短横题。独立组件不改变相机，不捕获滚轮/点击/触屏。题字均使用楷体CSS栈，根层可注入自带楷体。

正文按实际新Blender的15/7/9/9个叙事节点分配，第三卷排除“参考全景”重复marker。第一卷山野、御苑、腊日、史传与洛阳；第二卷御花、宫墙、私园、宴游与民间静赏；第三卷吉祥、婚嫁、岁时、器物、德性；第四卷人花、沉香亭、宫廷、马嵬与兴衰，均遵循源文稿顺序。正文按分句形成短题跋，不省略字词，默认最多68字、窄画心按容量再细分。页面到达题跋区间后以CSS650ms淡显淡隐，减少动态时180ms；反向或直接seek也按同一轨道更新。progress≥.982退题，留给画卷结尾的定格和落印。

## 验证与边界

node scripts/validate-new-narrative.mjs实际7项通过，验证DOCX身份、25段逐字覆盖、响应式分句不丢标点和空格、四卷节点顺序/连续区间/正反seek/结尾退题、CSS过渡及输入穿透。默认数据为59个短题跋，窄画心会进一步细分。映射报告的进度基于原Blender帧范围，运行时根据实际prepare后的stops重新计算。

该脚本是文本/数据与CSS合同校验，不证明题字在真实画面中完全避让。实际留白区域、文字不遮主体、手机短画心可读性与渐显效果仍须由主任务在新资产接入后运行浏览器截图验证；不能拿此CPU通过替代画面验收。
