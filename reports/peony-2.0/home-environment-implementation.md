# 书房铺满取景与自然环境实现

首页原留边来自`StudyRoomRenderer.resize`的contain相机FOV：原比例居中装入窗口，1440×900上下留空，较宽屏左右留空；手机还另有向上偏移。容器本身已是`fixed; inset:0`，单改CSS宽高不能解决。

现改为参考相机的等比例cover取景，并保留3.5%出血覆盖微观察的边缘。画面没有拉伸，参考素材与投影结构保留；异于16:9的窗口会自然裁去部分边缘，极窄/极宽窗口不可能同时保留整幅构图。横屏题签仍按真实3D投影定位并限制在视口内，所有竖屏以可读的2×2真实按钮布局承接四个入口。

环境实现：

- 香炉位置使用两片细分曲面薄烟，顶点连续卷曲，片内噪声缓慢上行、向左弥散并逐渐消失，取代13个独立圆烟团。此为实时烟气网格，不是视频。
- 工笔色调的不对称曲面单瓣具有顶点设色；36—55秒错峰飘落、轻微翻转和前后距离差，主要沿两侧进入，保持标题区安静。
- 前景两角牡丹枝叶只在明确的局部遮罩内做微幅曲面偏移，不平移书房、桌案、人物或建筑。
- 微尘分相位小幅漂移，灯光约20秒低强度变化；与花瓣、烟气保持同向的平缓侧风。
- 首页静置环境最多30Hz重绘，观察和仪式镜头保留逐帧响应。环境关闭、系统reduce、后台及进入画卷后停止环境时钟和相应RAF；释放清理纹理、几何、材质和监听。

`node scripts/validate-home-layout.mjs`实际通过10种尺寸、30组观察边缘覆盖、按钮独立边界、连续烟气结构及真实Room构造/加载/off/reduce/hidden/离场/释放方法检查，GPU和DOM使用stub。TypeScript实际通过。该CPU检查不承担GLSL、像素或FPS结论；本轮实际浏览器另由validation-projection-home.json的13组和validation-runtime-new.json的30组核实，手机仍为浏览器触屏/视口模拟。旧首页几何、原图SHA、四按钮、shader失败门及可访问性约束仍保留在`validate-projection-home.mjs`，另增全视口cover与连续薄烟断言。

画卷内追加单瓣的重力轴与源视角保持一致，随机角度只作用于花瓣本身，不把重力转成横漂或上升；新增慢翻转与同向风，并在CPU逐瓣检查。新版2.0导出完成后，实际打开其六张独立花瓣、飘带和单灯纹理，核对当前24个对象的精确名称、材质图及SHA，再将revision审核门更新为`peony-2.0-2026-10-22`。名单外所有原人物、宫苑、花石和灯市组合都不追加环境矩阵动画，原作者动画与材质入场进度仍按源轨道运行。完整清单在同目录的`motion-source-review.json`。

最终2.0数据实际通过`npm run test:new-motion`的9组CPU检查：40个正文节点×3种宽高比共120次覆盖、80个独立单瓣的下落/同向风、未绑定的314个源对象矩阵保持、四卷off/reduce/hidden/end清理与真实SceneRenderer每帧至多一次纹理上传。`npm run test:projection-home:static`保留的原图身份/哈希检查通过，`npx tsc -b`与负责文件的`git diff --check`通过。本节上述证据限于CPU；本轮真实浏览器及性能结果另见本目录README，不宣称持续60FPS。
