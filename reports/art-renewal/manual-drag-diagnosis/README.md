# C6 桌面手动拖动诊断 · 2026-10-23 10:00–10:10

本轮确认两个真实问题：时间轴节点按钮覆盖连续拖动区域；真实画面拖动在贴图首次使用时出现同步 WebP 解码与 GPU 上传长停顿。仅作定位，尚未修改产品。全部三轮原画、源码、C6 包前后 SHA 均不变；实际浏览器 Chrome 156.0.8078.47，GPU 为 ANGLE / NVIDIA GeForce RTX 5070 Ti / D3D11。

权威入口为 [summary.json](summary.json)。它明确保留 15 个观察窗口的范围、原始报告位置与 SHA、事件目标、进度范围、请求、长任务和前后输入绑定。原始完整 rAF/事件 JSON 与 98 MB trace 留在 ignored `tmp/manual-drag-diagnosis/`；本目录保存紧凑派生证据、原字节 CPU profile 和三份当次驱动，见 [manifest.json](manifest.json)。[profile-summary.json](profile-summary.json) 是原 trace / CPU profile 的逐窗口与逐长任务汇总，分析脚本也已保留。

## 实际观察

1. 在 1920×1080 / DPR1 与 2042×1083 / DPR1.25，原生鼠标于约 78% 的时间轴按下时都命中 `BUTTON`。180 次移动没有触发 range `input`，松手后停在节点 `13 · 史实与传说` 的精确进度 `.7859741978167384`。这四个首轮窗口是交互反例，不是成功跨越 78%–90% 的性能测试。CSS 中 marker 的 20×26px 点击区以 z4 覆盖高度24px、z3 的 range，解释了命中事实。
2. 真正从画面拖动，以及将起点避开节点后的时间轴拖动，均跨过目标区间并出现长停顿。CPU 采样中：正拖 110ms 长任务含5次 WebP 解码76.606ms，`texSubImage2D` self93.718ms；暖回拖176ms长任务含7次 WebP 解码135.825ms，`texSubImage2D` self171.046ms；另一回拖149ms含6次解码112.82ms，上传self138.077ms。解码处于上传调用所在主线程任务中；两者嵌套，不得相加当总耗时。
3. 这些停顿至少出现在 `.786` 与 `.871` 附近，不能全部归因于 `.844–.855` 的非零原生 Glare 区间。当前卷 Glare35份非零1920×1080 RGB16F场本身约415MiB，是额外压力，但不是这次 WebP 解码的格式。原速自动播放也出现约121ms停顿，故不只是输入事件处理卡顿。
4. 暖回拖仍发起14个资源请求，其中10个为 Glare。当前可见纹理已经约238MB，而淘汰规则的总预算为160MiB；非当前可见且不在预取集的资源会马上进入淘汰条件。该代码与重复资源请求一致，但本轮未增加逐资源 dispose hook，不能把每次请求逐一断言为某个具体 dispose 的后果。
5. 采样窗口的单次 Layout≤0.19ms、UpdateLayoutTree≤0.65ms、GC≤4ms，着色器查询也远小于图片首次使用开销。此证据不支持优先更改题跋排版、作者材质、阴影或降低像素上限。

## 最小候选与保护边界

- 将时间轴离散节点入口与连续拖带分开，保留节点点击、键盘访问和标题；不能直接禁用节点事件以假装修复。
- 在常规图片和源材质 `encoding=image` 两处，实验 `image.decode()` 后才作为可使用纹理交付；再评估有界、逐张 `renderer.initTexture()` 提前准备，避免同一首次绘制批量解码5–7张。显式 decode 不保证浏览器永不重新解码，预上传仍可能有同步成本，必须先做同源隔离 A/B。
- 评估与当前必需可见纹理独立的、有界近期使用保留预算；Glare 可另评估按方向预取。不能用无限内存缓存代替问题定位。
- 任一采用都必须保持原资产字节、half-float场、颜色空间、flipY、mipmap、相机、源时钟、原帧门控与取消语义，随后重跑严格59帧/243结构及生命周期。候选尚未通过，不可把本报告写成 C7 性能验收。

## 测量边界

测量时用真实受信任鼠标 pointer 手势，没有产品 API/原型覆盖或加速时钟。第二轮在测量前用常规 DOM `input` 事件定位起点，测量中的手势仍是受信任 pointer。仅一轮开启1ms CPU采样和CDP trace，其开销已单独标注。计数器约100ms刷新，报告的是 renderer 提交数量；页面 rAF、提交与物理屏幕呈现是不同指标，不把截图率或任何一项当显示FPS。冷场表示新页面/WebGL context，未清理 OS、磁盘或驱动缓存。用户物理截图的原 CSS 尺寸未知，2042×1083/DPR1.25只是桌面近似覆盖。
