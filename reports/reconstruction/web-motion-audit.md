# 网页动效审查与实施设计

审查日期：2026-10-19。范围：当前本地源码、四卷 `scene.json`、纹理文件、项目工程记忆及既有测试。起点 HEAD 为 `9f632a0`，工作树已有启动冲突、相对路径与自适应修复；本审查不回滚这些变更，也未修改前端。本报告是代码与数据审查，图像边缘、主体完整度和叙事可读性须结合逐图审校与浏览器关键画面判定，不能用文件名代替视觉结论。

## 1. 当前架构与实际行为

| 模块 | 已实现 | 对本次重构的约束 |
| --- | --- | --- |
| `src/App.tsx` | 四卷切换、真实分镜、进度条、上一/下一景、自动展卷、卷末卡、文化抽屉、全屏 | 保留现有 UI 与按钮行为；增加可独立暂停的画中轻动，不能把“暂停展卷”误当作已暂停所有动画 |
| `src/hooks/useScrollController.ts` | 一份进度状态、目标值指数趋近、按卷会话进度、自动展卷、手动停止、隐藏页停播 | 动效订阅同一 progress；不得引入第二套相机路线或另一个会覆盖用户输入的播放进度 |

现有 renderer 每帧检查，但仅在 `dirty` 时实际绘制。`dirty` 来自进度、尺寸、纹理及指针变化。原 Blender 动画以 `sourceProgress` 采样：停下游观，动画也停在该源帧。因此当前有交互运动和少量源动画，没有独立低频环境时间、四卷气韵配置或停留时的画内呼吸。

## 3. 当前缺口与风险

1. 没有与 progress 分离的画内动效时钟，因此停止输入后没有持续呼吸。
2. 没有可审计的“图层 → 叙事节点 → 动态类型 → 上限”配置，若按文件名泛匹配容易晃动人物/建筑或两次叠加原动画。
3. 渲染器 `prefers-reduced-motion` 只在构造时读取，没有监听运行中偏好改变；滚动 hook 则已有监听。需统一策略。
4. 页面隐藏时自动展卷会停止，但 renderer 与 hook 的 RAF 仍继续排队，缺少明确的后台停帧与恢复基准；持续环境动效加入后必须解决。
5. 无“暂停画中轻动”控制。自动展卷暂停仅冻结路线，对新增低频循环不够。需要可键盘操作、aria-pressed 明确的独立开关。
6. 纹理失败进入 `errorUrls` 后本卷不再重试，只提示刷新；manifest 失败及 WebGL 上下文丢失也缺少局部恢复入口。短暂网络失败不应迫使整页重置阅读进度。
7. 已有扩大视锥、最多 4 并行纹理、约 160 MiB 目标 LRU 与 12 秒过期；可见资源不强制卸载，160 MiB 不是硬上限。不能增加整卷预加载、第二份全卷解码或每帧视锥扫描。
8. 大量透明平面可能产生 overdraw；几何统计和构建成功不能证明画面流畅，更不能证明没有硬边。
9. 切章已有 dispose、abort、CSS3D 清理与 `forceContextLoss`，新增资源、媒体监听、可见性监听、请求和恢复事件也须纳入同一生命周期。
10. 既有 CSS 减少动效规则处理了 UI，但不能自动处理 Three.js；UI 淡入淡出也不构成“网页画内动效已完成”的证据。

## 4. 推荐实现结构

建议新增独立模块，先只启用第一卷样板，样板视觉验收后再扩展：

| 建议模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| `src/data/motionProfiles.ts` | 四卷强度、环境色、速度、每节点包络、显式网格绑定、参与图层用途与位移上限 | 不改文化正文、原几何与相机 |
| `src/scene/MotionDirector.ts` | 从基础矩阵计算小幅局部位移/转角/透明度；按独立低频时间及阅读区间求值；可即时复位 | 不产生新 route、不累计覆盖上帧变换 |
| `src/scene/AtmosphereLayer.ts` | 独立云气/稀疏花瓣/水线等已审核资源，按章节/分镜世界锚点放置；不捕获指针 | 不用全屏发光或粒子雨掩盖主体边缘问题 |
| `src/scene/SceneRenderer.ts` 接缝 | 调度同一 render、相机、纹理系统；前后台/降动效/暂停；资源失败与 context 恢复 | 不另起多个同时跑的动画循环 |
| `ScrollViewport` 与 App 小幅接线 | 传入独立动效偏好；错误“重试展卷”入口；保留当前位置恢复 | 不重新设计装裱与进度业务 |

### 4.1 坐标、层级与变换

- 每个绑定项明确 `meshName`、图层类型、叙事用途、动作、幅度和 pivot。禁止只用“名称含花/带/云”自动让整卷动起来。
- 基础矩阵取源 manifest 或当前 `sourceProgress` 动画采样，每帧采用 `base × localDelta`，而非从上一帧继续加旋转。减少动效、关闭轻动、切章时复位为基底，防止漂移和抖动。
- 花枝、灯彩以根部/顶部为局部支点；有硬边、缺边或一张平面包含人物与建筑时先修资产，不能用位移暴露缺底。合并人物不作整片转动。
- 基本云层可用原 RGBA 资源小幅水平漂移与很浅的透明度变化，左右变化不超过其安全外扩区。不同卷沿原相机局部左右/上下或明确世界轴运动，避免第三/四卷轴向误用。
- 新连接层位于真实相邻阅读节点之间，按远/中/近景设少数世界平面，与原场景咬合；视锥之外不更新、不请求纹理。画内近景可遮挡边缘，但不得覆盖核心人物脸部、文化题字或把留白填满。
- 稀疏花瓣使用小量可复用透明纹理和合批几何/Points；粒子位置由稳定种子求值。禁止大量 DOM、每帧重建 geometry、逐瓣 React setState 或高分辨率 canvas 循环生成。
- 一次新分镜触发仅改变极轻的局部强度包络，输入停止后自然衰减；不触发群像动作，不改变阅读位置。

### 4.2 四卷差异配置

| 卷 | 首批必做的克制变化 | 可用资源与主题约束 | 初始设计上限（待样板实测调整） |
| --- | --- | --- | --- |
| 一 | 庄重缓云、通过审校的花枝微摆、偶发稀瓣 | 御苑与牡丹初兴；保留原金带/绢帛动画 | 可见花瓣约 5–8；枝摆 ≤0.25°；云周期 28–42s |
| 二 | 薄云/春风、独立花枝轻摆、少量轻瓣 | 清雅游赏，不加舞台灯光、竞花和喧闹密度 | 花瓣约 4–6；枝摆 ≤0.35°；周期 18–30s |
| 三 | 花灯小幅摆、独立锦带微动、少数水线呼吸 | 灯彩/织物/器物的吉祥意象，器物和凤凰图案主体静止 | 灯摆 ≤0.3°；锦带 ≤0.18°；花瓣约 2–4 |
| 四 | 前段丰润但轻；第5景起逐步减缓、疏瓣、疏云；尾段水线与留白 | 盛—衰通过同一主题资源密度、速度、透明度的连续递减表达，避免突然黑屏/褪成灰片 | 前段花瓣约 7–10，末段 0–2；末段时间速度约前段 0.35–0.5 |

这些数值是有边界的实现起点，并非已验证效果。若某类独立资产尚不可用，就不承诺已实现该类动作；优先实现已审查对象与过渡气韵。

### 4.3 可访问性、后台与用户控制

- 动态监听 `prefers-reduced-motion`；减少动效时停用所有时间驱动漂移/摆动/粒子及指针视差，原相机仍响应用户明确输入；滚轮与分镜即时定位，自动展卷仍由用户明确启用并可暂停。
- 提供“画中轻动”按钮，与“自动展卷”分开；关闭后不再推进环境时钟，恢复时连续接上，不跳到墙钟绝对时间。暂停偏好可本地保存，并通过 try/catch 容忍存储不可用。
- `document.hidden`、WebGL context lost、场景销毁均取消 rAF；恢复可见后重置帧时间，以免大 dt 导致瞬移。后台停止自动展卷的现有行为保留。
- 切卷柔和过渡应在当前画心内完成，减少动效偏好直接切换；旧场景淡出后释放，而非同时驻留两整卷纹理。加载失败时保持清晰提示与重试按钮，避免无限加载遮罩。
- WebGL 失去上下文时阻止默认销毁并显示恢复提示；恢复后重建当前卷、恢复原 progress。网络错误允许有限局部重试，失败资源不发起每帧请求；手动重试重置失败集合，销毁后到达的回调只释放纹理。

## 5. 性能预算与验收证据

预算是实现门槛，结果须从运行时采集，不能以“用了 Three.js”推断通过。

| 项目 | 设计预算/原则 | 证据 |
| --- | --- | --- |
| 纹理 | 保留按视锥加载、4并发、160MiB目标 LRU、DPR≤1.65；新动效共享图集，不另载整卷 | 记录请求 URL、加载/纹理数、estimated bytes，首屏不请求全卷，离开远景后旧纹理被释放 |
| 动态开销 | 环境轻动目标约30Hz；输入/相机保留流畅响应；只更新当前可见少数绑定，过渡区新增可见透明平面约≤6 | 同一机型同一节点开/关动效比较帧时、draw calls、活跃对象；后台计数冻结 |
| 低端与窄窗 | 根据画心尺寸降低花瓣数/DPR或停用次级层；不开启复杂后处理与额外灯光 | 375×667、1280×720、1920×1080 无溢出、画面裁切和控制失效；速度慢时自动降级不影响游观 |
| 资源释放 | 切卷后前卷 geometry/material/texture/事件/RAF 清理 | 四卷往返多轮 renderer.info、活动canvas/监听/请求稳定；不能只看 JS heap |
| 画面质量 | 同节点停留两时刻有局部轻微变化，固定建筑/人物主体稳定；边缘安全区不露出 | 第一卷样板前后截图及间隔帧对比；四卷各首/中/尾及跨景边界截图；高风险图层局部放大 |

建议可验证测试分两层：

1. 保留 `npm run build`、`npm run validate:assets`、`npm test`、`npm run test:startup`，覆盖类型、原资产结构/路线、启动端口与路径修复。它们不验证新增画内动态、透明边缘或GPU速度。
2. 新增针对动作基底复位、第四卷节点包络、减少动效不推进、可见性恢复不跳时的纯配置/时钟测试；浏览器验证静止时实际画面变化、手动暂停冻结、prefers-reduced-motion 动态切换、后台 RAF 停止与恢复、触发纹理404后重试、manifest失败重试、WebGL context loss/restore、滚轮/拖拽/惯性/键盘/自动展卷/分镜/切章/卷末/抽屉无回归。运行时计数应可只读观察，不把内部诊断文字放进用户流程。

## 6. 执行顺序与当前边界

1. 完成所有原图审查表与问题截图，形成“保留/修复/重生成”依据；本代码审查不自行把候选名改成最终修复结论。
2. 第一卷完成透明边缘/安全外扩与连接层样板后，增加独立配置、MotionDirector、AtmosphereLayer 及最小 renderer 接线，只启用第一卷。
3. 第一卷运行截图、暂停/后台/减少动效/恢复、真实交互和资源释放均通过，展示样板结果，再依同规范扩展二、三、四卷；第四卷单独检查第5景至尾声的盛衰递进。
4. 最后联调四卷，输出实际动作绑定清单、资产用途、运行命令、构建与浏览器证据、关键帧截图。没有通过图像审查或运行测试的效果不写成已完成。
