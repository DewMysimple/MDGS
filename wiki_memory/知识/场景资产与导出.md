# 场景资产与导出

## 运行资产与外部来源

网页读取 `public/assets/chapter-1..4/scene.json` 和同目录 `textures/*.webp`。manifest 是真实图像平面/网格、列主序世界矩阵、xyzw四元数、相机采样、分镜和动画；纹理引用为相对路径，263个引用本次逐项检查存在。网页无需 F:盘源工程即可运行。最大纹理边2048px，alpha保留，实际总字节149516783。来源：结构校验报告及当前四份scene.json。

四个原 `.blend` 位于用户外部 `F:/牡丹/场景blender搭建/` 下；精确路径在 `scripts/export_blender.py`/`audit_blender.py`，素材恢复目录在同级素材来源配置中。原图字节缓存 `.asset-cache/`、node_modules、dist与Python缓存均不进Git；公开WebP与scene.json必须进Git，否则新克隆不能运行。

## 重导出

在根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/run-export.ps1
# 可覆盖脚本默认的本机可执行文件路径
powershell -ExecutionPolicy Bypass -File ./scripts/run-export.ps1 -Blender '<blender.exe>' -Python '<python.exe>' -RenderReferences
```

默认 Blender 是 `F:/Blender/blender.exe`；Python 默认值属于原开发机，换机需传参数。Python图像优化依赖Pillow，最终验证依赖Node；导出依赖四个源文件及素材目录，不从网络补造国画。流水为审查→程序材质检查→导出→几何索引→WebP→程序透明纹理恢复→统计→验证，可选参考渲染960×540。源 `.blend` 不保存覆盖。详见脚本与 `reports/assets-readme.md`。

## 相机与渲染不变量

`prepareScene.ts` 从原阅读标记开始，用空间距离替代电影停留时间，使滚轮持续推进；方向 +X/+X/+Y/−Y 保持各卷原映射。一卷网页结束帧13474、二卷5521，避开原片末尾抬升/大幅拉远；完整原路径仍在源JSON，不能用统一方向或虚构轨迹替换。

`SceneRenderer.ts` 使用无光照MeshBasicMaterial、sRGB纹理、透明双面平面。原FONT几何保留导出但网页不直接渲染长横排，文化长文在抽屉。透明云气、接地影和第四卷留白等6个程序透明材质经 `restore_procedural.py` 还原为RGBA；删掉该步骤会重现矩形色块。浏览器并未完整复制Blender灯光、噪声和全部程序着色。

DPR上限1.65，扩大视锥预取、4并行纹理、约160MiB目标LRU；可见纹理不强卸载。切卷释放几何/材质/纹理/CSS3D层及WebGL上下文。保留 `textureRefreshPending`，否则100ms节流可能漏掉最后一次seek后的纹理刷新。实际GPU峰值未测量，不能把预算称为硬上限。

## 验证与边界

`npm run validate:assets` 验证文件、尺寸、UV/索引、矩阵、相机、分镜/动画；`npm test` 验证prepareScene起止、节点单调、结束帧及不改原几何。两者本次首次提交前通过，未重新执行Blender导出或跨显卡测试。结构测试不能证明绘画构图、全部交互或性能；改相机/尺寸还需浏览器截图。
