# 四卷素材核对与首卷画面补全

## 原因与用户选择

用户指出第一卷约48%、Blender第1451帧截图中花车、马、队伍、旗幡、亭桥与曲水缺失，要求比对四卷并补全。起点main `3d8086c`，工作树干净，保留用户此前仅本地交付、不推送的要求。

源文件SHA与网页清单一致。只读检查发现被漏导出的主体 `主体 · 03_中央花车巡游与曲水` 在Blender工作视图可见，整数帧1—3024的 `hide_render` 均为true；旧导出以render可见性决定是否导出，故漏掉该图。用户明确要求以提供的工作视图截图补回这一处，因此作为单对象例外恢复，并保留原 `neverVisibleGeometry` 审计事实；不将其他隐藏对象一律显示。四份原blend未保存修改。

## 核对和修复

四卷主场景MESH逐项核对，修复前源/网页数量分别为152/151、58/58、79/79、52/52。第一卷唯一遗漏为上述主体，其余三卷没有主场景MESH缺项。第一、三、四卷隐藏的路径为无材质、无厚度编辑曲线；第三卷另有9个MESH仅在独立分镜预览场景，不被连续主场景引用，其原图与主场景对应图SHA一致，不补入以免重复。

已有340个对象的源材质与网页程序绑定、244份图片的来源/哈希/尺寸/解码RGBA、34份程序场的哈希及解压尺寸均通过；新恢复对象另行独立逐值核对364个索引顶点、256个三角面、UV、法线、矩阵、材质程序与原图像素。恢复原图为无损WebP，不添加入场动画。可复建步骤见 `reports/viewport-restore/README.md`。另一项独立渲染修复使必需资源失败时保留完整画面并支持重试，不把这一缺陷误认成首卷漏导出的原因。

## 验证与边界

- Blender 5.2.3 只读打开四个原件，以原相机渲染四卷各三个源帧（首卷193/1451/2377，二卷275/1296/1994，三卷241/961/1681，四卷178/585/1351），与2K网页同帧并排检查：抽样主体和位置对应。首卷1451按用户工作视图补回的花车有意不同于同帧原最终渲染；全部源帧的视觉逐帧等价未验证，透明度、光照、景深和色彩可能存在差异。
- `node scripts/validate-viewport-restore.mjs --recovery tmp/viewport-restore`、`npm run test:scene-stability`、`npm run test:scroll-input`、`npm run test:peony2-clock`通过，包含资源失败/重试与既有显隐、阴影、时钟检查。
- 最终打包Electron独立配置在首卷48%截图确认补回主体；720p、30/60各6秒自动播放采样无超过80ms的画卷提交间隔及资源等待。12项桌面验收通过，含四卷离线交互、全屏和花笺；原图打包、ZIP CRC和解压哈希校验通过。短时采样不代表全程或所有设备均无卡顿。
- 静态清单不能证明所有动画帧的遮挡或着色器计算完全等价；现有旧 `validate-peony2-fidelity.mjs` 和原生参考绑定早期源版本，不作为本轮验证。
